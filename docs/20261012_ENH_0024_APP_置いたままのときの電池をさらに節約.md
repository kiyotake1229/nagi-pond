# 置いたままのときの電池をさらに節約

- 管理番号: #0024
- 種類: ENH（機能改善）
- 対象: アプリ本体（APP）
- 作成日: 2026-10-12
- 関連: #0020（省電力）、#0022（計測で見つけた）

## 概要

省電力（#0020）で描く回数は減ったが、計測（#0022）で CPU の仕事量が思ったほど減っていないと分かった。描かないコマのあいだもアプリが呼ばれ続けていたこと、すりガラスのぼかしを描き直していたことを直し、毎秒120回などの速い画面の端末でも描くのを毎秒60回までにした。置いたままのときの CPU の仕事量は、省電力を入れる前と比べて、30秒後で約44%、5分後で約59%少なくなった。

## 対象ファイル

- `index.html`（`frame` / `schedule` / `frameGap` / `poke`、CSS）
- `tools/test.mjs`（画面の書き換えの再現を本物に近づけ、テスト2件を追加。計34件）

## 変更内容

- 描くまでに間があるときは、その手前までタイマーで休み、画面の書き換え（毎秒60回）のたびに呼ばれないようにした（`schedule`）。おやすみ中は0.5秒に1回だけ起きる
- 画面の書き換えが毎秒120回・90回などの端末でも、描くのは毎秒60回まで（省電力がオフでも）。Android の上位機種などで効く
- 操作が無く上の帯と下のメニューが薄くなりきったら（7秒＋1.8秒）、すりガラスのぼかしを外す（`body.still`）。30%の薄さなので見た目はほぼ変わらない。触ればすぐ戻る
- テスト用の仮の環境で、画面の書き換えのときに「その時点で頼まれているもの」だけを呼ぶようにした（タイマーで休んでいる分は呼ばない）
- 追加したテスト: 「毎秒120回・90回の端末でも毎秒60回まで」「描かないコマのあいだは休み、おやすみ中は0.5秒に1回だけ」。それぞれ、直した部分を元に戻すと失敗することを確かめた
