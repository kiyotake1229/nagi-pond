# プライバシーマニフェストの追加とiOSのビルド確認の強化（凪の池）

- 管理番号: #0033
- 種類: ENH（機能改善）
- 対象: iOSアプリ（IOS）
- 作成日: 2026-11-06
- 関連: #0005（iOS アプリ化）、#0008（GitHub Pages・ビルド確認）

## 概要

App Store へのアップロードで求められる申告を iOS アプリにそろえた。プライバシーマニフェスト（`PrivacyInfo.xcprivacy`。トラッキングなし・収集データなし・「理由の申告が要る API」の利用理由）をアプリに入れた。GitHub Actions のビルド確認（Xcode 26）で、ビルドが通ることと、できたアプリにこれらが入っていることを確かめた。

## 対象ファイル

- `ios-app/ios/App/App/PrivacyInfo.xcprivacy`（新規）
- `ios-app/ios/App/App.xcodeproj/project.pbxproj`（App ターゲットの Resources に登録）
- `.github/workflows/ios-build.yml`（Xcode 26 に固定し、実機向けビルドと申告の確認を追加）
- `README.md`（iOS の行）
- `ios-app/岩崎さんへの引き渡し手順.md`（プライバシーの章に1行）

## 変更内容

- **プライバシーマニフェスト**（`PrivacyInfo.xcprivacy`）: トラッキングなし（`NSPrivacyTracking = false`）、トラッキング用のドメインなし、収集データなし（App Store Connect の「データを収集しません」と同じ）。申告した「理由の申告が要る API」は次のとおり
  - UserDefaults（`NSPrivacyAccessedAPICategoryUserDefaults`、`CA92.1`: アプリ自身のデータの読み書き）
  - ファイルの日時（`NSPrivacyAccessedAPICategoryFileTimestamp`、`C617.1`: アプリのコンテナ内のファイルの情報）
- **申告の決め方**: アプリが使う部品（Capacitor 7.6.9 本体、`@capacitor/filesystem` 7.1.9、`@capacitor/haptics` 7.0.5、`@capacitor/local-notifications` 7.0.7、`@capacitor/preferences` 7.0.4、`@capacitor/share` 7.0.4、`@capacitor/status-bar` 7.0.6）を `ios-app/package.json` と `package-lock.json` で確かめ、それぞれの iOS 側のソースを調べた。`@capacitor/preferences` が UserDefaults（端末内の設定の保存）を、`@capacitor/filesystem` はファイルの作成・更新日時を返す機能（`stat`）を持っているので、アプリがその機能を呼ばなくてもファイルの日時の申告が要る（このアプリでは池の写真を共有するときの一時ファイルの書き込みに使っている）。ほかの部品は理由の申告が要る API を使っていない
  - 全アプリ共通の決まりとして UserDefaults（`CA92.1`）は必ず申告する。理由の申告が足りないと、アップロード時に ITMS-91053（理由の申告が無い）で止められる（2024年5月から）。Apple が見ているのは「使っているのに申告が無い」ことで、多めに申告して止められることはない。あとから `@capacitor/preferences` などを足したときの申告漏れも防げる
  - `@capacitor/filesystem` を足すときは、ファイルの日時（`NSPrivacyAccessedAPICategoryFileTimestamp`、`C617.1`）も足す。足し忘れるとビルド確認が失敗する（下記）
- **Xcode のプロジェクトへの登録**: 手元に Xcode が無いため、CocoaPods に入っている xcodeproj（Ruby）で App ターゲットの Resources に追加した（そなえ帳と同じ方法）。保存のときに、中身が空の `packageReferences` の項目が外れることがある（Swift Package は使っていないので影響なし）
- **暗号化の申告**: `Info.plist` の `ITSAppUsesNonExemptEncryption = NO` は以前から入っている（通信しないので暗号化を使っていない）。今回、できたアプリに入っていることをビルド確認で毎回確かめるようにした
- **ビルド確認（GitHub Actions）を作り直した**: これまでは `macos-latest`（その時々の新しい Xcode）でシミュレータ向けだけをビルドしていた。**Xcode 26 に固定**し（Capacitor 7 は UIScene に対応していないため、Xcode 27 の SDK ではビルドしない。そなえ帳と同じ）、実機向け（Release）のビルドも足した
- **ビルド確認で毎回確かめること**（`.github/workflows/ios-build.yml`）:
  - Xcode のプロジェクトで `PrivacyInfo.xcprivacy` が App ターゲットの Resources に入っていること、ファイルが正しい形式であること
  - できたアプリ（`App.app`）に `PrivacyInfo.xcprivacy` が入り、トラッキングなし・トラッキング用ドメインなし・収集データなしであること
  - UserDefaults（CA92.1）の申告があること。`CapacitorPreferences` が入っていれば UserDefaults（CA92.1）、`CapacitorFilesystem` が入っていればファイルの日時（C617.1）の申告が無いと失敗にする（プラグインを足したのにマニフェストを直し忘れるのを防ぐ）
  - `Info.plist` の `ITSAppUsesNonExemptEncryption` が false、Bundle ID が `work.ltv.nagi`、使っているプラグインのフレームワークが入っていること
  - `NSPhotoLibraryAddUsageDescription` があること（共有シートで写真を保存するときに無いと落ちる）
- 作業は Dropbox の外の作業用コピーで行い、`node_modules/` は Dropbox に置いていない
