# iOS 版の控えから記録が戻らない（控えを初期状態で上書きしていた）

- 管理番号: #0011
- 種類: BUG（バグ修正）
- 対象: iOSアプリ（IOS）
- 作成日: 2026-10-09
- 関連: #0005（保存の二重化を入れた変更）

## 概要

iOS 版は、WebView の保存領域（localStorage）が消えたときの備えとして、アプリ用の保存領域（Preferences）にも控えを書いていた。しかし起動の順番が悪く、控えから戻す処理が一度も動かないうえ、起動のたびに控えを「鯉3匹の初期状態」で上書きしてしまう作りだった。WebView の保存領域が消えると、池がまるごと初期状態に戻る。

## 対象ファイル

- `index.html`（保存の処理: `load` / `save` / `initNativeStore`）

## 変更内容

- 原因: 起動直後に初期の鯉を足して `save()` していたため、控えを確かめる時点では localStorage に必ず何か入っていて「消えていない」と判断していた。さらに、その `save()` が 0.4 秒後に控えも初期状態で上書きしていた
- 起動時に localStorage に読めるデータがあったか（`hadLocal`）を、初期の鯉を足す前に覚えておく
- アプリ版では、控えを確かめ終わるまで（`nativeReady`）控えに書かない
- `initNativeStore`: WebView 側にデータが無く、控えに鯉のデータがあれば、それで池をまるごと入れ替える（`applyState`）。再読み込みはしない（localStorage に書けない環境で、繰り返し読み込み直すのを避ける）
- 控えへの書き込みなど、iOS の部品の呼び出しで失敗しても画面に影響しないようにした（`quiet`）
